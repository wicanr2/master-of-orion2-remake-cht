# Ship Initiative 設定串接規格

## 目的與文字邊界

把既有 `GameSettings.ShipInitiative` 接到快速結算與格子戰術的玩家可見回合順序。
本功能不新增內嵌玩家文案；若日後需要提示，必須先加入 `assets/i18n/ui.json`，Go 只以鍵值取用。

## 證據契約

- 已證實：原版關閉時依戰鬥雙方分批行動；開啟時合併艦艇後降冪排序。
- 已證實：原版比較器同分回傳 0，排序分數讀戰鬥記錄 raw `+0x3B` 與 `+0x34 / 10`。
- 手冊契約：玩家可見主動權為 Beam Attack + 10×Combat Speed；能量吸收器在開啟時
  可跨回合累積，關閉時未於該戰鬥回合使用便清空。
- 未知／停止線：seeking-missile 的逐 tick raw 狀態、網路同步與平台繪圖呼叫不做逐指令重製。

## Remake 行為

1. 關閉（原版預設）：快速結算維持雙方分批行動，不在同側內另做主動權排序；格子戰術
   維持我方完成後敵方回擊。每個完整戰鬥回合結束時，雙方未使用的能量吸收器儲能歸零。
2. 開啟：快速結算與格子戰術都把雙方存活艦艇放入同一個穩定降冪行動序列，艦艇若在輪到前
   被擊沉便不再行動。同分維持建立序；remake 的合併建立序固定為玩家艦列在敵艦之前，這是
   raw combat-list 建立端尚未證實時的決定性 tie-break，不冒稱原版已證實。
3. 快速結算使用 `combatant.initiative`；格子戰術在每回合建列時，以 `CombatShip.Attack` 與
   `TacticalEffectiveSpeed` 重算同一個 `gamedata.CombatInitiative` 公式，使牽引／停滯造成的
   當前速度變化能進入下一回合順序，而不是永遠沿用開場快照。

## 格子戰術佇列

- 每艘 `CombatShip` 進場時取得單場暫態 ID。合併佇列只保存 ID、陣營與本回合主動權，不能保存
  切片索引；戰損壓縮後必須以 ID 重新定位，避免擊沉前一艘船後讓後續行動指向錯船。
- 敵方行動不等待玩家點擊：從回合首或玩家 DONE／成功開火後，自動執行所有排在下一艘玩家艦
  之前的敵艦，再把選取權交給該玩家艦。敵艦沿用現行 typed 武器與最脆弱目標策略；AI 移動不是
  Ship Initiative 的證據範圍，不在本切片自創。
- WAIT 只延後目前玩家艦：把該行動移到本回合合併佇列尾端，不標成 DONE；若其間有敵艦，敵艦
  會先行動。DONE 與成功開火都消費目前行動。點擊其他我方艦不得跳過目前行動者。
- 佇列耗盡才進入既有回合交界；戰機、腐蝕黏液、充能、狀態重算與點防禦重置只執行一次。
  關閉設定時完全保留原有「我方逐艦 → 敵方整隊」流程。

## 驗收

- 純規則測試：關閉時保持雙方原序；開啟時可出現敵艦先於我艦行動，且同分穩定。
- 狀態測試：關閉時回合末清空儲能；開啟時保留。
- 格子戰術測試：高主動權敵艦能在低主動權玩家艦之前行動；高主動權玩家艦先行；WAIT 能跨過
  敵艦；被先擊沉的待行動艦不會還擊；關閉模式的舊逐艦測試保持不變。
- 全套 `go test ./...` 與 Docker 清理、擁有權檢查。
