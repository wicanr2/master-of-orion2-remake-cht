# 原版特殊裝置表(執行檔一手資料)

`Orion2.exe` 資料段 `0x17EEE0` 起的 39 筆特殊裝置紀錄,每筆 47 (0x2F) 位元組。
程式碼落點:[`internal/gamedata/special_devices.go`](../../internal/gamedata/special_devices.go)。

先前 `shell.SpecialOptions` 每一列的成本都標著「remake 值:執行檔的元件表還沒挖到」
——這份文件就是那句話的終點。

## 紀錄格式

```
+0   dd     名稱字串指標(全表同值,IDA 重定位後的產物,不是資料)
+4   dw     裝置編號 = SpecialDevices 列舉值(0..39,連號)
+6   dw     解鎖科技編號 = Technology 列舉值
+8   6×dw   空間,依艦體等級:巡防 / 驅逐 / 巡洋 / 戰艦 / 泰坦 / 末日之星
+20  6×dw   成本(BC),同上六級
+32  15 位元組  其餘欄位(未解讀:圖示索引、AI 權重之類)
```

## 欄位偏移是怎麼定出來的

不是照著長度猜的,三個獨立訊號指向同一組偏移:

| 訊號 | 位址 | 說明 |
|---|---|---|
| `Special_Devices_Available_` | `0x5F9EA` | 讀 `word_17EEE6[i*0x2F]`(= +6)當索引去查 `[帝國紀錄+0x117+科技編號] == 3` → **+6 是科技編號**,而 3 = 已研究 |
| `Init_Internal_Space_` | `0x36470` | 讀 +8 那一欄 → **+8 起是空間** |
| 戰鬥艙那一列 | — | +8 欄是**負數**;手冊寫「add equipment space without increasing the hull size」,負佔格正是「加空間」的實作 |

## 兩道交叉驗證

兩道都是**先抽完才發現對得上**,不是拿來湊參數的:

1. **39 筆的科技編號逐筆對上 remake 既有的 `TECH_*` 列舉,零不符。**
   那份列舉先前是從別的來源建的,兩邊獨立。(釘在 `special_devices_test.go` 的
   `exeSpecialDeviceTech`,寫的是**執行檔讀出來的整數**而非 `TECH_*` 常數,列舉一動就會紅。)
2. **戰鬥艙的負佔格 = 艦體空間的一半**,連截斷都一樣:
   艦體 25/60/120/250/500/1200(**抄自手冊 p.121**)→ 戰鬥艙 −12/−30/−60/−125/−250/−600,
   其中 12 = floor(25/2)。兩份來源獨立而小數點處理一致。

## 巨型通量器:同一趟挖出來的第二件事

`Total_Design_Space_`(`0x6E81F`)只有一件事會改變可用空間:

```asm
movsx eax, word_180020[hullIdx*24h]   ; 艦體基礎空間
cmp   byte ptr [edx+ebx+170h], 3       ; 0x170 − 0x117 = 89 = TECH_MEGAFLUXERS
jnz   short skip
imul  eax, 7Dh                         ; ×125
mov   ebx, 64h
cdq
idiv  ebx                              ; ÷100(整數除法,截斷)
```

手冊寫「Megafluxers increase the amount of space on each ship by **25%**」——比例對上了,
而**截斷方式只有執行檔給得出來**:巡防艦 25 → 31(31.25 截掉),不是四捨五入的 31。

⚠ 巨型通量器 (+25%) 與戰鬥艙 (+50%) 看起來是同一類東西,**實作位置不同**:
前者乘在「可用空間」上,後者是「已用空間」那一側的負值。混在一起做會算錯。

## 沒解讀的部分

+32 之後的 15 位元組留白。從幾筆的值看得出至少有兩個欄位(例:阿基里斯瞄準器尾端
`01 00 … 01 64 00`、廣域干擾器 `09 00 26 00 15 00 … 04 64 00`),但沒有找到讀取它們的
函式,所以不猜。要用到再回去查 xref。

## 這張表沒有涵蓋什麼

MOO2 把「牽引光束」「停滯力場」「反飛彈火箭」歸在**武器表**(stride 0x1C,`word_17F80D`
那一欄是它的科技編號),不在這 39 筆裡。remake 的 `SpecialOptions` 把它們放在同一個下拉,
是 UI 的取捨,不是原版分類——查它們的空間/成本要去武器表。
