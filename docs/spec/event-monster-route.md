# 事件怪物 owner 8 航行規格

## 目標

依 `docs/re/event-monster-route-audit-20260825.md`，將事件 19–23 從「立即盤據目標星」改成
可存檔、可推進、抵達後才成為星系守衛的航行狀態。

## 已證實規則

- 事件仍先保存已抽中的受害帝國及殖民星；該星是目的地，不是出生位置。
- 五種事件怪物均以 owner 8 共用戰略航速 1 parsec/turn。
- 航程為出生座標至目標星的 `ceil(直線距離)` parsecs，至少一回合。
- 航行中不得由 `MonsterAtStar`、拓殖阻擋或停泊太空鰻 age consumer 當作已在目標星。
- ETA 每個正常回合只減一次；從 1 變 0 的同回合抵達並開始盤據目的星。
- 抵達後太空鰻 age 為 0；其他怪物保留原始結構。航行欄位必須隨 JSON／多人快照往返。

## 外圍出生座標近似

- remake 沒有原版視窗捲動 globals，因此使用目前銀河 raw 寬高及目標星正規化座標。
- 由事件專用可存檔亂數選水平或垂直邊界，再選正負方向；出生點位於該邊界外 `1..5` parsecs，
  另一軸保留目標座標。ETA 仍以已證實的 30 raw units/parsec 與無條件進位計算。
- 這只近似 `sub_A1762` 的玩家可見外圍進場，不宣稱重播原版同一 RNG 序列或 raw 座標。

## 資料與 UI 契約

- `MonsterGuard.StarIndex` 永遠是目的星；`TransitETA>0` 表示航行中，0 表示停泊。
- 航行物件仍存在於 `GameSession.Monsters`，讓全局太空鰻四艘上限可計入 active ship；但只有
  停泊太空鰻增齡。
- 建立訊息使用「正朝星系前進」；抵達時追加玩家可見訊息，不得在出發回合宣稱已盤據。
- 舊 JSON 缺少 `TransitETA` 時零值代表既有停泊守衛，保持相容。

## 驗收

1. 事件建立後目標星尚未被 `MonsterAtStar` 視為守衛，且 ETA 大於零。
2. ETA 按回合遞減一次；抵達後才阻擋拓殖並顯示抵達訊息。
3. owner 8 固定速度測試不因怪物種類而改變。
4. 航行太空鰻不增齡，但計入全銀河四艘上限；抵達後才開始增齡。
5. JSON／多人快照保留 ETA；舊快照仍視為停泊。
6. 全專案測試、`git diff --check`、擁有權及 Docker 清理通過。
