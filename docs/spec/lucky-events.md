# Lucky 隨機事件規格

證據來源：[`docs/re/lucky-event-audit-20260825.md`](../re/lucky-event-audit-20260825.md)。

## 玩家可見規則

- 一般事件仍從全部已實作、非播報事件抽樣；Lucky 不得把一般池預先過濾成全好。
- 一般路徑抽到壞事件且目標是 Lucky 玩家時，該候選取消；共同的最多五次候選迴圈仍可繼續，
  但不會把壞事件直接轉換成好事件。
- Lucky 玩家每回合累積一點計數器，並在一般事件擲骰前檢查額外好事件。
- 標準 remake 對局目前只有「Random Events 與 Antaran Attacks 皆開」的執行設定，因此用原版
  除數 8。純規則函式必須保留原版四種設定組合，避免把目前 UI 限制誤寫成 oracle。
- 成功條件是 `Random(1000) <= counter/divisor`。成功立即清零；`Turn-1` 未滿 50 時仍不觸發
  額外事件，與原版控制流一致。
- `DisableEvents` 是 remake 測試用的硬關閉旗標，不冒充原版兩個獨立設定；開啟時不累積、
  不擲骰也不觸發事件。

## 狀態與持久化

- `LuckyEventCounter` 屬於玩家帝國，必須隨 JSON 存檔與熱座席位往返。
- 舊存檔缺欄位時以 0 開始，保持向後相容。
- Lucky 擲骰使用既有可持久化 `eventRand`，不可另建未存進度的亂數源。

## 驗收

- 純規則測試覆蓋四種除數、整除邊界與 1..1000 擲骰邊界。
- 測試一般池包含壞事件、額外池只含好事件，以及 Lucky 壞事件取消。
- 測試第 50 回合閘門、成功清零、未成功累積、JSON 與熱座往返。
