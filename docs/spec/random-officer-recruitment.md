# 隨機領袖招募規格

依據：`docs/re/random-officer-recruitment-audit-20260825.md`。

## 回合規則

1. 每個玩家回合結算一次招募檢查；前五回合機率為零。
2. 機率為 `(距上次 offer + 1 + 種族修正 + Famous 加成) / (目前兩類領袖總數 + 1)`，採整數除法；負值視為零。
3. 以獨立、可存檔的 `officerRand` 抽 `[0,100)`；只有抽值小於機率才產生 offer。機率未達正值、八席全滿或沒有可用候選時不消耗不必要的候選抽取。
4. 候選前綴為 `Turn/5 + 10 + playerSlotCount`，Charismatic 加 10；否則 Repulsive 減半；最後夾在實際候選數內。最多隨機嘗試 100 次。
5. 已受雇、已在 offer 池、類型席位已滿的候選不可再次出現。原版同時只有一個當前 offer；remake 保留 `MercPool` 容器相容性，但新 offer 會取代尚未處理的舊 offer。

## 相容與驗證

- 舊存檔缺少亂數抽取計數時從既有 `EventSeed` 的固定子流開始；讀檔後序列必須延續。
- 保留 `MercOfferedIdx` JSON／熱座欄位供舊存檔與荒難領袖事件相容，但正常招募不再把它當循序候選指標。
- 測試涵蓋：前五回合、種族修正、Famous 一般／進階、兩類四席、候選不重複、offer 取代、存檔亂數續接。
