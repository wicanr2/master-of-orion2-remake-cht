# 外交對談外部文案與文字安全框規格

## 文案契約

- 固定玩家文案只存於 `assets/i18n/ui.json`，鍵值前綴為 `diplomacy.audience.`。
- `diplomacyOption` 只保存 `textKey` 與規則層 `action`；不得保存中英文 label。
- 使節開場句以 `%s` 接收外部顯示名。未知 session 的示範種族名亦由 catalog 提供。
- `internal/shell` 回傳的動態外交結果維持規則層資料，不在 UI 重新寫死另一份句子。

## 幾何契約

- 標題、使節名、兩行回應、目前協議列、提議按鈕、終止協議按鈕及離開按鈕，各自具有
  明確 `textSafeRect`。
- 提議與終止協議文字框由對應點擊熱區推導，水平與垂直中心必須一致；單行過長時截斷。
- 最多五顆終止協議按鈕固定落在 x=`16..624`、y=`398..422`；不得與最後一列提議
  （底緣 y=`392`）重疊，也不得讓第五顆按鈕從 x=`640` 開始跑出畫布。
- 回應區最多兩行，第二行必須套用省略策略；不得只靠 painter clipping。

## 驗證

- 雙語 catalog 必須含全部固定鍵，格式模板的 `%` 數量固定。
- 靜態測試禁止外交對談切片新增 `.tr(` 或直接硬編既有固定文案。
- 以最長英文提議及繁中提議驗證按鈕字墨落在安全框內；正常畫廊仍是最終視覺 gate。
