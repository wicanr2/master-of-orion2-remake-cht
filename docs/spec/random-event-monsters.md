# 隨機事件 19–23 怪獸入侵規格

## 目標

依 `docs/re/random-event-monsters-audit-20260825.md`，移除「第一顆無主星」與太空鰻借用
變形蟲的自創行為，讓事件目標、種類、帝國路由與存檔狀態符合可表示的原版規則。

## 規則

- 最早相對回合依事件 19／22／20／23／21 為 `100／150／200／250／300`；候選閘門沿用
  已證實的一般事件排程，超空間亂流存在時不得建立怪獸事件。
- 先由一般事件權重選受害帝國，再在該帝國所有有效殖民地中作 reservoir sampling；保存並
  使用其星系索引。不得改挑無主星或目前玩家母星。
- 事件 19–23 對應變形蟲、水晶、巨龍、太空鰻、九頭蛇；太空鰻是獨立種類，不能共用
  `MonsterAmoeba` 身分。
- 玩家、非目前熱座席位與 AI 都必須能成為受害帝國；事件報告保存正確 target kind/index。
- `MonsterGuard` 與 JSON 必須保留怪獸種類、目標星及剩餘結構。
- 太空鰻每一個 active 個體各保存 age。停泊模型中每回合加一；age 恰好 30 時歸零，若全銀河
  太空鰻少於 4 艘，於母體同星系新增一艘 age 0 太空鰻。新生個體不得在建立回合再次增齡。
- remake 以單一 `MonsterGuard` 聚合同星太空鰻時，必須保存 `Count` 與逐體 `EelAges`，並把
  新生個體的完整初始結構加入總結構；不能只以固定每 30 回合補血替代個體數與錯開年齡。

## 明示近似

- 原版 owner 8 首次航行現由 `MonsterGuard.TransitETA` 表示，抵達前不盤據目標星；外圍出生
  座標因缺少原版視窗捲動 globals，依 `docs/spec/event-monster-route.md` 採銀河邊界近似。
- `MonsterGuard` 以同星聚合數量／結構表示多支 owner 8 太空鰻，而非逐艦戰術 actor；已有其他
  怪獸的殖民星仍不列入候選。一般星圖守衛怪獸不會位於有效殖民星，跨種類堆疊仍屬表示限制。
- 太空鰻不攻擊殖民地已在 battle-side selector 與 remake 同步排除；其他怪物抵達後的固定防禦、
  三輪轟炸、`/40` 與殖民地傷亡依 `docs/spec/event-monster-colony-battle.md` 接線。精確 blueprint
  與途中逐座標截擊仍待 owner 8 下游垂直鏈，不宣稱完成數值 parity。

## 驗收

1. 五事件 ID 對應五個不同種類及五個最早回合。
2. 玩家事件只會落在玩家有效殖民星，不會挑第一顆無主星。
3. 多殖民地固定亂數可選到非第一個候選，證明不是固定索引。
4. AI 與非目前熱座席位各至少一條建立與 JSON 往返測試。
5. 太空鰻有獨立種類、名稱與零攻擊能力；不進一般星圖守衛怪獸池。
6. 分裂測 age 29→30、30→0、全局 4 艘上限、同星結構增加、錯開 age、JSON／多人快照。
7. 全專案測試、`git diff --check`、擁有權與 Docker 清理通過。
