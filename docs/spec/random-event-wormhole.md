# 隨機事件 28「蟲洞」規格

證據來源：[`../re/random-event-wormhole-audit-20260825.md`](../re/random-event-wormhole-audit-20260825.md)。

## 適用與選擇

1. 使用一般好事件選出的玩家、非目前熱座或 AI 帝國。
2. 跨維度帝國不適用；沒有 `ETA>0` 且目的星合法的航行艦隊時不適用。
3. 候選權重是各合格艦隊的艦艇數：等價於在全部合格航行艦中 reservoir sampling 一艘，再以
   該船所屬艦隊作效果目標。不得固定選目前操作艦隊，也不得讓空艦隊進入候選。

## 效果

- 抽中的整支艦隊在事件建立回合立即抵達：`AtStar=DestStar`、`DestStar=-1`、`ETA=0`。
- 玩家正常抵達所需的探索／接觸／戰鬥後續仍走既有抵達 consumer；若目前資料模型沒有可安全
  分離的同回合 hook，至少必須保存立即抵達的星圖狀態並明標後續時序限制，不可退回 ETA=1。
- AI 同步更新 `FleetStar/FleetDestStar/FleetETA`；非目前熱座只修改其席位快照，不切換目前席位。
- 事件訊息與 report 保存實際帝國、目的星及艦數；事件 28 是一次性事件，不建立 persistent record。

## 驗收

1. 兩支玩家艦隊中只有被權重抽中的一支立即抵達；未選艦隊不變。
2. 艦數較多的艦隊按船數進入 reservoir，並有固定亂數測試防止退化成均勻按艦隊抽選。
3. 非目前熱座與 AI 各一條立即抵達測試；目前席位不被切換。
4. 跨維度帝國、無航行艦隊、空艦隊與非法目的星均失敗且不改狀態。
5. 全專案測試、格式、擁有權與 Docker 清理通過。
