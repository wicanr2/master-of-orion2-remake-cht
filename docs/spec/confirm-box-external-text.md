# 共用是／否確認框外部文案與安全框規格

## 行為

1. 確認框覆蓋下層畫面；框外點擊不得傳到下層。
2. 點擊 Y 熱區執行 `onYes`，點擊 N 熱區執行 `onNo`；callback 沒有轉場時返回下層。
3. hover 只切換原版按鈕資產 frame，不改變熱區。

## 文案來源

- `confirm.button.yes` 與 `confirm.button.no` 必須由 `assets/i18n/ui.json` 提供雙語值。
- 呼叫端正文必須由各功能自己的穩定 JSON 鍵格式化；`confirmScreen` 只接受已完成格式化的
  動態訊息，不保存任何功能專用句子。
- Go 不得內嵌玩家可見的「是／否」或 `YES／NO`。

## 繪製與後備

- 有 `CONFIRM.LBX` 的英文模式露出原版烘字，不重畫按鈕文字。
- 繁中模式擦除烘字後，以 JSON 文案重畫；文字框由 51×21 點擊熱區推導，中心必須完全相同。
- `CONFIRM.LBX#1/#2` 缺席時，兩種語言都必須畫出可見按鈕底、邊框與 JSON 標籤；不可留下
  可點但不可見的熱區。
- 正文維持 224×126 安全框、12px 字級、16px 行距；固定行數後以省略號收束。這是明標的
  remake 文字排版近似。

## 驗證

- IDA 原始立即數與函式邊界可由匯出腳本重生。
- 雙語按鈕鍵存在；正文與按鈕的實際 glyph ink 不超出安全框。
- 靜態測試禁止 `confirmbox.go` 直接呼叫字型繪製或重新內嵌固定按鈕文案。
- 有資產與缺資產兩條繪製路徑均須抽樣，點擊熱區與 callback 行為由規則測試覆蓋。
