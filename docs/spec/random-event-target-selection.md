# 隨機事件帝國目標選擇規格

證據來源：[`docs/re/random-event-target-audit-20260825.md`](../re/random-event-target-audit-20260825.md)。

## 純規則

1. 輸入依原版玩家槽順序提供總人口與 eligibility；人口是各有效殖民地人口總和。
2. 壞事件的 eligibility 必須同時滿足存活且沒有活動中的壞事件；好事件只要求存活。
3. 候選少於兩個時，移除極值後無法抽選，回報空池。
4. 壞事件移除最低人口帝國，權重為與最低人口差值的平方。
5. 好事件移除最高人口帝國，權重為與最高人口差值的平方。
6. 差值平方完成後才交給原版 `sub_586D4` 對應的權重正規化與抽樣。
7. Lucky 不得在壞事件建池時預先移除；抽中 Lucky 後才取消該候選。

## 執行期接線邊界

- 全局一般事件每個銀河回合只能排程一次，不可因熱座席位數重複擲排程骰。
- Lucky 計數先對所有存活 Lucky 帝國累加，再按執行期槽序擲骰；第一個成功者是唯一強制目標。
- 執行期槽序為真人席位順序後接剩餘 AI。單人局的目前玩家是第一槽；熱座局先同步目前載入席位
  回 `Seats[ActiveSeat]`，避免用上次換人時的舊快照計算人口。
- 選中的目標必須能指向目前真人、非目前熱座席位或 AI 帝國；事件效果、播報與持續 record
  必須指向同一目標。
- 若 AI 薄模型缺少某事件所需欄位，該事件效果保持未完成並消耗候選，不得默默改打目前真人。
- 事件 9／24 及原版另行指定目標的特殊路徑不套一般人口權重；沒有閉合其專用目標時保持明示
  未完成，不得假借一般目標公式。

## 本輪驗收

- 純規則測試覆蓋好／壞兩種極值、差平方、eligibility 與退化池。
- 測試全局排程不隨熱座席位數重複、Lucky 第一成功槽停止、非目前席位回寫及 AI 已支援欄位回寫。
- AI 尚缺的事件效果逐項回報不適用；只有具備真實資料欄位與測試的效果可以列為已接。
