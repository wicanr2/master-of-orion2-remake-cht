# 誠實現況評估(moo2 remake)

> 起於 2026-07-04 使用者實測回饋「還原度約 20%」。**該 20% 是接原版 LBX 美術前的快照,已被 2026-07-05~12 多輪超越,勿再當現況錨點。** 本文保留核心紀律 + 現況 + 誠實 caveat;逐輪「怎麼接的」細節見 git log 與 `WORKLIST.md`,不在此重複佔篇幅。

## 核心紀律(此文存在的理由,rulebook/65)

還原度**只以「對原版實測比對」驗收,不看單元測試綠 / 新增系統數**。曾多輪用「加自製系統 + 測試綠 + headless 有畫面」謊報進度,但那些係數多是自編近似值(程式碼自標「remake 調校值」),測試只證自製邏輯自洽、不證對齊原版——使用者一玩就見差異。**還原 = 對齊原版,不是長出新東西。誠實標注每個數字來源,自編的就說是自編的。**

## 現況(2026-07-12)

可玩的多帝國 4X 迴圈(headless 探針驗:玩家 + 3 AI 各自擴張、經濟健康、可經三條勝利路徑贏一局、無 panic):

- **① 音樂 ✅**:PCM 場景 BGM(menu/galaxy/diplo/combat)+ 按鈕/戰鬥音效;僅曲目↔場景精確身分待人耳定案。
- **② 忠實新遊戲流程 ✅**:版本選擇 1.3/1.5 → 難度/星系 → 14 族肖像選擇 → 自訂點數 → 命名旗色 → 真母星(人口職務模型農4/工1/科3,SAVE10 校準)。
- **④ gameplay 子系統全接**(非死碼):經濟(建築效果/重力/士氣/礦產/地形改造/污染/成長/收入/指揮點數)、科技抉擇樹、戰鬥(beam/飛彈/球狀分流 + 艦艇佔格 + 武器 mod)、地面戰(陸戰隊/戰車/軌道轟炸)、拓殖、多 AI(N=3,含 AI-vs-AI 關係矩陣)、間諜偷科技、領袖技能、三勝利路徑(征服/議會忠實搖擺票/安塔蘭反攻)。
- **經濟校準**(手冊考據 + SAVE10.GAM oracle + moo2sim 探針):每科研 3、開局 BC 50、人頭基礎收入 1 BC/人、稅率預設 15、指揮基礎供給 5。60 回合玩家 BC 健康爬升(55→419)。詳見 `docs/knowledge-base/original-gameplay-reference.md` §7、`docs/knowledge-base/manual-cht/`。


CLAUDE.md 明列「允許在主選單選擇中文/英文」。中文方向早就做完,英文方向這天才補——
在此之前 `-lang en` 跑起來,**多數 remake 自繪畫面仍然整片中文**。

**現況:`cmd/moo2` 的 UI 層做完了,`internal/` 引擎層還沒。**

### 兩條路徑,只有一條天生雙語

| 路徑 | 做法 | 英文模式 |
|---|---|---|
| **overlay**(`overlayScreen` / `runOverlay`) | 擦掉原版美術上烘死的英文,疊中文 | **自動正確**——整段擦字疊字被 `lang == Traditional` 擋掉,原版英文直接露出來 |
| **自繪**(remake 自己畫的面板) | `fnt.Draw*` 直接畫程式裡的字串 | 先前**仍是中文**——底下沒有原版英文可露,字串本身寫死中文 |

overlay 那條的英文不是「翻譯」,是原版點陣美術本體,字型字距都是對的。

### 兩種修法,優先用第一種

- **讓路**:畫面底下是原版美術、英文烘在圖上時,英文模式整段跳過擦底疊字。畫面 100% 是
  1996 年的點陣字,比用 Noto 重畫更像原版,而且通常只要一個 `if`。
  用在:遊戲選單(GAME.LBX 六顆鈕)、多人設定(按鈕+標題帶)、種族選擇(14 顆族名鈕 +
  `SELECT RACE` 橫幅)、載入儲存(LOAD/CANCEL)、戰術戰鬥控制列(AUTO/SCAN/BOARD/…)。
- **`b.tr(zh, en)`**(`cmd/moo2/interactive.go`):底下沒有原版英文可露時才用。

### 順帶修掉的兩個中文模式看不出來的 bug

- 種族選擇的標題橫幅(RACESEL 資產 33)**從來沒被畫過**,只是被擦底的方塊蓋住。中文模式
  看不出來,英文模式一讓路就露出一片空白。
- `diplomatRaceIndex` 原本是手寫的 14-case switch,和 `raceSelectList` 是兩份會漂移的表;
  改成由後者推導(順序本來就一致),順帶能認英文族名。艦體名也一樣(原本三份對照表)。

### 剩下的:引擎層自己就講中文

`internal/` 有 **2,188 條**寫死中文,其中 1,501 條是星名池(829)+ 艦名池(672)——那兩份是
原版英文池的譯本,英文原文在原始資料裡,接得回來。剩下約 690 條是引擎產生的顯示字串
(`session.go` 228、`gamedata/buildings.go` 83、`colonization.go` 61、`gamedata/events.go` 44…)。

實測看得到的症狀(`-lang en` 的截圖廊):星圖上的星名、殖民地畫面的建築名與建造項目、
行星氣候/礦產值、熱座交接的席位名 `Next: 第 2 位玩家(布拉西人)`——**UI 層單獨修不掉這些**。

正解不是把 `tr()` 灑進引擎(引擎不該知道語言),而是讓引擎回**鍵值**、UI 端負責繪成文字;
或至少給那些資料表加 `En` 欄。那是獨立的一輪,沒有跟這輪混在一起做。

### 怎麼量

`cmd/moo2/lang_gap_test.go` 是**棘輪**:用 go/ast 數「沒被 `tr()` 包住、又真的會畫到畫面上」
的中文字面值,超過 `langGapCeiling` 就 fail,只能往下調。

⚠ **別拿 `grep '\"...\"' | wc -l` 或 `tr(` 的數量當覆蓋率**:`tr("繼續", "CONTINUE")` 本身
就含中文字面值,補得越多 grep 的數字反而不動;而「讓路」那條路徑一個 `tr()` 都不需要
(`gamemenu.go` 就是 0 個 `tr()` 但英文模式完全正確)。

目前棘輪 **16**,而那 16 條全是偵測器分不出來的東西——查表 key(`shipClassZH`、
自訂種族的「政府型態」)、dev-only 單畫面檢視模式的視窗標題、以及英文模式跑不到的分支。
**真正的 UI 缺口是 0**,但那不等於「英文模式做完了」,見上一節。

驗收仍然是跑 `-lang en` 的過場截圖廊逐張看,不是看棘輪數字:

```bash
# 兩種語言各跑一次,逐張比對(中文模式應該逐像素不變,存檔時間戳除外)
/tmp/moo2 -game -data /data -font <ttc> -lang en -gamegallery <dir-en>
/tmp/moo2 -game -data /data -font <ttc>          -gamegallery <dir-zh>
```

`cmd/moo2/lang_coverage_test.go` 擋的是另一種漏:新增一族 / 一個旗色時漏填英文欄——
不會編譯失敗、中文模式也完全正常,只有英文模式會出現空白或中文。

### 兩個踩過的坑

1. **英文比中文長**:`hotseat.go` 那句英文說明第一版就溢出 320px 面板右緣。每加一段英文,
   要用 `-lang en` 跑截圖廊看實際排版,不要只看編譯過。
2. **`i18n.English` 是 `Lang` 的 Go 零值**(`English Lang = iota`)。`&sceneBuilder{session: s}`
   預設就是英文模式——production 端任何忘了設 `lang` 的建構路徑都會靜默變英文。
   `report_test.go` 因此加了明寫 lang 的規定與一條回歸測試。

## 鐵律

驗收看原版實測不看測試綠;不把「新增系統」當還原進度;誠實標數字來源;**還原度 % 待使用者對原版實測定案,不自評**。
