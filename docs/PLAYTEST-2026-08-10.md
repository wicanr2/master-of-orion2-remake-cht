# 2026-08-10 remake／原版雙測試員抽樣報告

本輪依使用者要求採抽樣驗證，不執行 `go test ./...` 全套。兩位測試員分開使用
Docker 環境：測試員 A 驗證 remake；測試員 B 驗證正版原版與靜態資產。兩邊都沒有修改
工作樹。

## 多人網路最低可玩鏈抽樣（2026-08-10）

- `internal/netplay`：以兩個實際測試程序建立 loopback TCP，驗證主機／客戶端握手、
  `turn_done` 傳遞、`turn_ready` 收集與錯席位／分歧拒絕。
- `internal/shell`：驗證共同快照還原、不同 UI 選取不造成網路指紋分歧，以及同一條
  `PlayerCommand` 由不同席位重播後維持相同狀態。
- `cmd/moo2`：在 Docker + Xvfb 通過網路流程的目標編譯／測試；主機共同開局、客戶端
  套用快照、正式 `networkWaitScreen` 與失敗即關閉路徑已接入。
- 本輪沒有宣稱重連、心跳、加密、NAT 穿透或原版 IPX／數據機／序列／TEN 相容；完整
  公網可靠性另列後續 scope。

## 測試員 B：原版對照

動態原版測試在啟動階段被 `VESA.COM` 阻塞：

| 路徑 | 結果 |
|---|---|
| `mm2-dosbox` 預設入口 | 入口執行不存在的 `mm2 E`，顯示 `Illegal command: mm2` |
| `Orion2.exe E`／EGA、不同 cycles | 顯示 `You must run VESA.COM.` |
| 零長度 `VESA.COM` 佔位檔 | 仍失敗，排除單純檔案存在檢查 |
| `Orion2.exe M`／`vgaonly` | 仍要求 `VESA.COM` |
| DOSBox-X `svga_s3` | 視窗可啟動但全黑，未進入有效 UI |
| `ORION95.EXE`／Wine | 停在 Wine 初始化／設定畫面 |

`find /private -iname "vesa.com" -o -iname "vesa*.com"` 退出碼為 0，但私有資料與既有
映像沒有 `VESA.COM`。因此本輪不宣稱已取得原版新局、星系、殖民地、外交、戰術或存檔
動態結果。

成功的正版靜態 LBX 抽樣：

- `MAINMENU.LBX`：44 資產、142 幀。
- `NEWGAME.LBX`：30 資產、36 幀；1.31 背景為 `#28`，1.5 為 `#31`。
- `STARBG.LBX`：6 張背景。
- `COMBAT.LBX`：23 資產、34 幀；控制列為 `#0`，調色盤為 `#11`。
- `CMBTSHP.LBX`：45 艦艇資產、900 幀；代表 360 個 20 幀方向動畫資產。
- `DIPLOMAT.LBX`：產生 643 張部分輸出，但未取得完整退出碼，列為未完成。

## 差異判定

| 面向 | Remake 抽樣 | 原版本輪證據 | 判定 |
|---|---|---|---|
| 主選單／新局 | 動態畫廊成功 | 靜態背景與資產成功解碼 | 畫面資產可比；動態差異待補 |
| 星系／殖民地／艦隊 | remake 轉場成功 | 無有效原版動態畫面 | 不宣稱規則／輸入等價 |
| 外交／現金餽贈 | remake 畫面與切片可跑 | 13 組原版外交資產靜態證據 | 不宣稱原版提案反應等價 |
| 戰術／戰機 | remake 戰術畫面與 PD 抽樣成功 | 戰鬥背景、控制列、艦艇方向資產成功解碼 | 戰機精確命中／傷害仍未由原版動態驗證 |
| 存檔／載入 | remake 示範存檔／載入畫面成功 | 原版 `SAVE10.GAM` 僅取得雜湊 | 不宣稱存檔格式／回合狀態等價 |

### 可直接作為差異追蹤的結論

Remake 目前可以作為可玩的跨平台版本與畫面導覽驗收；原版動態對照不是「通過」，而是
被缺少 `VESA.COM` 的環境阻塞。靜態 LBX 證據已支援主選單／新局／戰鬥／外交素材對照，
但不能取代原版實機的輸入、規則、戰機傷害與存檔測試。下一次若補齊 VESA runtime，應只
重跑上述未取得動態證據的節點，不需重做 remake 35 張畫廊。
