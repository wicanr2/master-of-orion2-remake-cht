# 一般隨機事件排程逆向稽核（2026-08-25）

## 問題與舊行為

remake 的 `advanceEvents` 長期使用每回合固定 30%。這個值沒有原版證據，而且會讓開局前 50
回合出現原版明確禁止的 GNN 隨機事件。本次沿 `Next_Turn_Calc_` 的直接 caller 閉合排程閘門、
難度公式、事件 ID 候選與重置時序。

## 證據契約

- 輸入：`Orion2.exe`
- SHA-256：`7ae2ac2e5904ca330009af2827279d889906b0b9b7a8854c38eb707a56e955b5`
- 工具：IDA Pro 9.4、IDAPython；位址皆為 IDA 線性位址
- 可重生腳本：`tools/ida/audit_event_schedule.py`
- 執行方式：複製 `.i64` 至一次性可寫目錄，原始 EXE／資料庫唯讀；不保存推測性改名。

## 已證實

### 回合入口與最早日期

- `Next_Turn_Calc_ @ 0x136B3` 在 `0x1375B` 呼叫 `sub_2230A @ 0x2230A`，並到
  `0x13802` 才增加 `dword_192FD8`。事件因此使用本回合增加前的星曆。
- 新局 `sub_C5F52 @ 0xC5F52` 尾跳 `sub_201A4 @ 0x201A4`，把事件最後日期
  `dword_19ACE8` 設成目前星曆，並把 `word_19ACEC` 清零。
- `sub_2230A` 要求相對起始星曆至少 50；remake 的 `Turn` 從 1 起算，所以對應
  `Turn-1 >= 50`，即最早在 `Turn == 51` 的結算檢查。

### 一般事件機率不是固定百分比

Random Events 開啟、沒有 Lucky 強制事件時：

1. 若目前星曆早於最後事件日期，直接不觸發。
2. 前五次檢查會逐次增加 `word_19ACEC`，但把日期差暫時視為 0；仍擲 `Random(512)`，
   因結果為 1..512，門檻 0 必定失敗。
3. 第六次起，以 `delta = currentDate - lastEventDate` 套用難度公式：

   | 難度 raw | 顯示 | 門檻 |
   |---:|---|---:|
   | 0 | Tutor | `delta/2` |
   | 1 | Easy | `(2*delta)/3` |
   | 2 | Average | `(3*delta)/4` |
   | 3 | Hard | `(4*delta)/5` |
   | 4 | Impossible | `(5*delta)/6` |

4. `Random(512) <= threshold` 才開始挑事件。整數除法在非負 delta 上皆向下取整。
5. 成功建立事件 record 時，`dword_19ACE8 = currentDate`、`word_19ACEC = 0`。
   候選全失敗則不重置，下一回合沿用增長後的 delta。

### 事件 ID 候選

- `0x2240A` 以 `Random(0x1D)` 取得 1..29，再減一成為事件 ID 0..28。
- 每次排程最多嘗試五個候選；不是先把適用事件過濾成較小陣列再等權抽樣。
- Tutor（raw 0）在 `0x22427..0x22434` 拒絕 `byte_180E84[id] == 0` 的壞事件。
- Lucky 強制事件也只接受 good flag；一般壞事件若 `sub_22D57 @ 0x22D57` 選中 Lucky
  玩家，該候選失敗，但仍回到共同的五次候選迴圈。因此舊文件所稱「完全不重抽」不精確：
  它不會把壞事件直接轉成好事件，但共同迴圈可以再抽到另一個候選。
- 明確最早日期限制：事件 2／24 為 200，19 為 100，22 為 150，20 為 200，23 為
  250，21 為 300（皆為相對起始星曆回合）。其餘適用條件仍由各事件 helper 判定。

## 保留邊界

- 原版是全銀河一次排程，再由 `sub_22D57` 在存活帝國間選目標；該函式的總人口來源、
  好／壞事件極值排除與差平方權重已另見
  [`random-event-target-audit-20260825.md`](random-event-target-audit-20260825.md)。remake 已接全局
  目標索引、熱座非目前席位及 AI 基本 BC／RP 回寫；AI 殖民地／艦隊／外交與持續 record 等
  複合效果仍不能由本次排程測試代替。
- 未實作事件在 remake 會視為候選失敗，仍計入五次上限。這保留原版 ID 抽樣形狀，但事件
  缺件會使實際播報率低於原版；不得把排程閉合寫成 29 種效果皆閉合。
