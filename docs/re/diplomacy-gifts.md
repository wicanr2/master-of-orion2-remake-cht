# 外交現金餽贈證據索引

## 範圍

本頁只記錄一次性現金餽贈的可追溯切片，不把科技、星系、勒索、AI
接受門檻或特殊貿易表的未知欄位混進來。證據等級沿用專案規則：已證實、
強推論、假說、未知。

### 已追回的原版比較常數

`sub_53146 @ 0x53146` 先以 `dword_197F98 + 0xEA9*empire` 的多個欄位、政府／性格表、
關係陣列與 `sub_E5E09` 組出最後評分，再在函式尾端以固定比較回傳四桶：

| 最終評分 | 原版回傳值 | 指令位置 |
|---:|---:|---|
| `< -75` | `0` | `0x533C4`／`0x533C9` |
| `-75 ≤ score < -50` | `2` | `0x533CF`／`0x533D4` |
| `-50 ≤ score < 0` | `1` | `0x533DD`／`0x533E2` |
| `score ≥ 0` | `3` | `0x533EB` |

這組門檻是**已證實**的評分回傳桶，不等於 remake 的 `Relation` 數值；`0x531E7` 的
`sub_1247A0(0x64)` 與前置欄位修正仍會改變輸入評分。

`sub_533F4 @ 0x533F4` 是另一個含亂數的外交測試：`0x53410` 使用 `0xC8` 上界，
`0x5345B` 比較 `word_180DB8[government]`，且 `dx > 0x64` 時再呼叫 `sub_51078`。
因此不能把它誤寫成另一個單一固定接受常數。

目前真正的外交回應函式 `sub_539D9 @ 0x539D9` 在 `0x53A92` 依 `var_4` 分成九種
模式。直接比較指令證實兩套狀態路徑：

| 狀態路徑 | 精確分支邊界 | 原始訊息／旗標效果 |
|---|---|---|
| `+0x627` 為 1／2 | `< -100`，或 `sub_53E96(...) == 6` | `0x53C7E`／`0x53C9D` → `0xA5`、失敗 |
| 同一路徑 | `-100 ≤ score < -50` | `0x53CC4`／`0x53CE9` → `0xA6` |
| 同一路徑 | `-50 ≤ score < -25` | `0x53D0F`／`0x53D7E` → `0xA7` |
| 同一路徑 | `-25 ≤ score < 0` | `0x53D85`／`0x53D8E` → `0xA8` |
| 同一路徑 | `score ≥ 0` | `0x53E38`／`0x53E3D` → `0xA9`、成功旗標 `1` |
| 另一狀態路徑 | `< -150`，或 `sub_53E96(...) == 6` | `0x53DA3` 跳回 `0x53C9D` → `0xA5` |
| 另一狀態路徑 | `-150 ≤ score < -75` | `0x53DC2` 後走 `0x53D7E` → `0xA7` |
| 另一狀態路徑 | `-75 ≤ score < 0` | `0x53E2D`／`0x53D8E` → `0xA8` |
| 另一狀態路徑 | `score ≥ 0` | `0x53E2D`／`0x53E38` → `0xA9`、成功旗標 `1` |

因此本輪可把「原版門檻常數」標為**已證實**；但哪個 `var_4` 模式是現金、科技、
條約或需求，以及每一種提案完整採用哪一條路徑，仍是**強推論／部分未知**。這不等於
已追回所有 AI end-to-end 接受公式。

## 重製對映

- `GameSession.OfferCashGift(enemy, amount)` 保留已證實的國庫轉移方向，並以
  玩家目前 BC 作為失敗即不變的資源邊界。
- 現有外交畫面提供 `贈送 10 BC`／`Gift 10 BC`，因目前畫面沒有可重用的
  數字輸入框；核心函式接受任意正整數，未來補輸入框時不需改交易模型。
- `Relation +5`（再套用已存在的魅力外交倍率）是**強推論的正規化**，不是把
  原版 `-50` 直接當成關係分數。接受／拒絕尚未接入，因此本切片視玩家送出後
  成功；工作表仍保留「完整一次性餽贈未知」標記。
