# Auto Select Colony 設定稽核（2026-08-27）

## 問題

`Auto Select Colony` 已可保存與切換，但 remake 沒有玩法讀取端。這一輪要確認原版究竟何時自動選取，以及玩家手動巡覽後是否仍保持開啟。

## 證據契約

- 輸入：`Orion2.exe`
- `Orion2.exe` SHA-256：`7ae2ac2e5904ca330009af2827279d889906b0b9b7a8854c38eb707a56e955b5`。
- 輸入 `.i64` SHA-256：`4a01791fcf877ed87a740a54748694ab34a02675e3117dac052aeaa3f883944e`；分析使用一次性可寫副本，私有執行檔與資料庫不進 Git。
- 工具：IDA Pro 9.4／IDAPython，DOS/4GW 映像的 IDA linear address。
- 原始名稱、位址、指令 bytes 與交叉參照皆由腳本非破壞性匯出；下列語意不回寫成 IDA 名稱。

## 已證實

1. 設定值是 `byte_199BE3 @ 0x199BE3`；`sub_127E1 @ 0x12825` 把預設設為 0。
2. `sub_12479 @ 0x12728..0x12731` 在設定非零時呼叫 `sub_123CE @ 0x123CE`。後者逐一走訪 stride `0x71` 的星系記錄，先把每顆星的八個 `+0x17` 選取槽設為 `0xFF`，再呼叫 `sub_7862B @ 0x7862B`。
3. `sub_7862B` 最多掃五個星系內項目；找到目前玩家擁有且有效的記錄後，把相對項目序號寫回星系記錄 `+0x17+player`。因此此設定不是單純保存值，而是建立每顆星的自動選取目標。
4. `sub_825A8 @ 0x826FF..0x82737`、`sub_86188 @ 0x86775..0x867B9` 都只在設定非零時呼叫 `sub_7819E @ 0x7819E` 取得該星、該玩家的自動目標；有目標時走 `sub_8310E @ 0x8310E`，否則走 `sub_83669 @ 0x83669` 的一般選星路徑。
5. `sub_876DB @ 0x876DE` 與 `sub_87720 @ 0x87724` 進入函式後立即把 `byte_199BE3` 清為 0，再以前／後方向尋找下一個 `record+0x16 < 6` 的星系並呼叫 `sub_83669`。這兩個函式由間接 UI callback 使用，直接交叉參照不足；但「手動巡覽先關閉設定」由原始寫入指令證實。

## 強推論與限制

- stride `0x71` 記錄、五個 `+0x4A` 項目與 `+0x17+player` 構成星系內可選項目索引；結合設定名稱與兩條消費端，將它解釋為「自動選取目前玩家在該星系的殖民地」屬強推論。
- 外部 `func_names.txt` 在這段把 `sub_7819E` 稱為 `Is_Combat_Ship_`、把 `sub_7862B` 稱為 `Set_All_Star_Relocations_`，與實際欄位讀寫及 caller 鏈衝突；文件只保留 raw 位址，不採這些名稱作證據。
- remake 沒有原版星系內多個圖示的選取堆疊。把自動目標映射成「點我方殖民星後直接進單一殖民地畫面」是介面轉接近似，不是原版逐畫面 parity。

## Remake 映射與驗證

- 開啟：星圖正常點擊我方殖民星時，選取該星並直接進入對應殖民地畫面。
- 關閉或非我方殖民星：維持既有星系資訊面板。
- F5／F6：依原版 writer 先關閉 `Auto Select Colony`，再只切換星圖選星。
- 以規則測試覆蓋開／關、非殖民星及手動巡覽清除；以正常畫廊抽查殖民地畫面入口。
