# 熱座真人帝國選擇：原版席位計數證據

## 證據範圍

- 輸入：`Orion2.exe`，SHA-256 `7ae2ac2e5904ca330009af2827279d889906b0b9b7a8854c38eb707a56e955b5`。
- 資料庫：`Orion2.exe.i64`，SHA-256 `4a01791fcf877ed87a740a54748694ab34a02675e3117dac052aeaa3f883944e`。
- 工具：IDA Pro 9.4／IDAPython；位址為 IDA linear、DOS/4GW 映像。
- 可重生匯出：`tools/ida/audit_hotseat_empire_selection.py`。腳本只讀既有資料庫，保留
  原始函式名、位址、指令與 bytes，不對 `.i64` 改名或寫註解。

## 已證實

`sub_121F0 @ 0x121F0..0x12227` 逐一掃描 `dword_197F98` 指向的帝國陣列；索引乘上
`0xEA9`，上限讀 `word_199998`。只有同時符合以下兩項才增加回傳計數：

- `0x1220A: 80 78 28 64`：`byte ptr [player+0x28] == 0x64`；
- `0x12210: 80 78 24 00`：`byte ptr [player+0x24] == 0`。

因此舊文件只寫「控制碼 100 就算真人」並不完整；精確契約是控制碼 100 且
`+0x24` 狀態為 0。`sub_12175` 在 `0x121A2` 呼叫此計數函式。

`sub_F5691 @ 0xF5691..0xF5777` 仍可證實多人模式設定會依選項寫入
`byte_199F3A` 與設定物件 `+0xF7..+0xFD`；這不等同於逐帝國選擇介面的版面證據。

## 強推論與停止線

- `+0x28 == 100` 強推論為真人控制碼；函式用途及既有外部符號支持此解釋。
- `+0x24 == 0` 的玩家可見名稱仍未知，本輪只保留原始偏移與比較值，不以猜測名稱
  寫回 IDA。
- remake 的 `hotseatEmpireSelectScreen` 是因 `GameSession` 資料模型不同而加入的
  接管清單轉接介面。原版證據支持「真人數由帝國狀態計得」，不支持現行清單的
  座標、配色或文案；這些均不得宣稱原版逐像素還原。
